# Enable Google sign-in for WMC

Guest play works while sign-in is unconfigured. You need a Supabase project and a Google Cloud project you control. These steps affect real external services and require dashboard access.

1. Create a Supabase project at supabase.com. In its SQL Editor, run the contents of `supabase/rider-profiles.sql` once. It creates a profile table, server-side validation and row-level security. Usernames are globally unique, lowercase, and contain 3–20 letters, numbers or underscores. The policies allow users to read and edit only their own profile.
2. In Supabase, open Authentication → URL Configuration. Set the Site URL to `https://ahad00010.github.io/WMC/`. Add BOTH `https://ahad00010.github.io/WMC/index.html` and `wmc://auth-callback` to the Redirect URLs allowlist. Add your own HTTPS website URL if hosting elsewhere. Save.
3. In Google Cloud Console, select or create a project. Set up the OAuth consent screen (branding, audience and contact information). If your app is in Testing mode, add the Google accounts you want to test as test users. For a public launch, follow Google's publishing and verification requirements.
4. In Google Cloud → APIs & Services → Credentials, create an OAuth client ID of type **Web application**. In Authorized JavaScript origins add `https://ahad00010.github.io`. In Authorized redirect URIs add the **Callback URL shown in Supabase Authentication → Sign In / Providers → Google**, usually `https://YOUR-PROJECT-REF.supabase.co/auth/v1/callback`. Do not put the WMC callback or Android custom scheme in Google's redirect URI field.
5. In Supabase Authentication → Sign In / Providers → Google, enable Google and enter the client ID and client secret from Google Cloud. Save the client secret only in Supabase, never in the repository or chat.
6. Find your Supabase project URL and **publishable/anon key** in the project's Connect or API settings. Set `url` and `anonKey` in `auth-config.js`, commit and deploy it. This key is public by design; never use a secret or `service_role` key on the website. The app relies on the SQL row-level security policies above.
7. Refresh the deployed website, click **Sign in with Google**, and create a rider profile. Test duplicate username rejection and sign-out. On Android, install a newly built APK containing the external-browser sign-in bridge; older APKs cannot return from Google sign-in. Sign in from inside that app and verify it returns to the game. The APK uses the `wmc://auth-callback` custom scheme; it is not a verified app link, so another app could claim that scheme. PKCE protects the authorization code from being redeemed without the verifier, but a verified HTTPS app link would improve routing security for a production app.

This setup allows user-chosen profiles, not multiplayer. Only the local rider is shown. Profile data is stored in your Supabase project, subject to its authentication and data-retention settings. Users can edit their profile or sign out in the menu. Existing sessions compare `index.html` for updates; when changing only `auth-config.js` or `profile.js`, also change `index.html` to trigger the old-session notice.
